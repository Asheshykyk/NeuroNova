## 1. Executive Summary & Audit Decisions

This document records the foundational security audit, the **Step 0 read-only inventory**, and the updated **Security-First Priority 1 Action Plan** for the TRUSTTRACE repository (`NeuroNova`).

### Key Audit Decisions & Constraints:
1. **Committed Keys are Permanently Compromised:**
   - Any private key committed to git history (`lab/compose.yaml`, `lab/contract-address.env`, `render.yaml`, `scripts/deploy-local.ts`) is publicly exposed.
   - **Decision:** Do not rewrite git history on this shared multi-person repository. Instead:
     - Rotate all keys.
     - Add a strict denylist guard in deployment scripts (e.g. `deploy-orchard.ts`) that halts execution if derived deployer or signer addresses match any known compromised key.
     - Never paste full 64-hex keys in terminal outputs, commits, or documentation.
2. **In-Process Tests Do Not Prove Quai Orchard:**
   - Quai Network Orchard testnet has **no active deployment and no confirmed transaction hash**.
   - The current `hardhat.config.cjs` compiles with Solidity `0.8.24` (`cancun`/`paris`), which exceeds Quai's documented limit of `0.8.19` / `0.8.20`.
   - **Decision:** Remove all "validated on Quai" or "deployed on Orchard" overclaims from documentation until real live deployment succeeds.
3. **Reconciled Test Baseline:**
   - The 48 Hardhat tests in `blockchain/test/` sat outside the 362 tests previously reported.
   - Combined with the 9 standalone checks, the blockchain suite contains **57 contract checks**, bringing the true monorepo regression baseline to **410 checks**.
4. **Toolchain & CI Guardrails:**
   - The repository uses **`npm` workspaces** (with `package-lock.json`). The orphaned `pnpm-workspace.yaml` and nested `package-lock.json` files must be cleaned up.
   - Pull-request CI must run **100% offline and in-process**, with Node.js pinned via `.nvmrc` and `engines`. Docker and live RPC jobs must be separated into manual/nightly workflows.

## 2. Answers to the Five Critical Audit Questions

### Q1: Is the repo on npm or pnpm, and which lockfile is committed?
* **Answer:** The repository uses **npm** (`npm workspaces` in `package.json`).
* **Evidence:** Root `package-lock.json` (`lockfileVersion: 3`, 445 KB) is committed. An orphaned `pnpm-workspace.yaml` exists from early scaffolding and must be deleted. Nested lockfiles exist in `apps/dashboard` and `services/verifier`.

### Q2: Where do the 33 Hardhat tests run today?
* **Answer:** They run via `npm run test:hardhat --prefix blockchain`.
* **Evidence:** The root `package.json` script `"test:blockchain"` was only invoking `contract-standalone.test.ts` (9 checks). The full Hardhat suite lives in `blockchain/test/` across:
  - `EvidenceAnchor.test.ts` (25 tests — source registration/revocation, sequence continuity, replay protection, and actual storage gas: 177,525 genesis / 163,867 chained).
  - `quai-orchard-smoke.test.ts` (11 tests — Cyprus-1 shard rules, domain separators, cross-chain checkpoints).
  - `BatchCommitmentVerifier.test.ts` (8 tests — OpenZeppelin EIP-712 + ECDSA).
  - `chain-reset.test.ts` (4 tests — divergent local history rejection).
  *Total in Hardhat: 48 passing tests + 9 standalone = 57 contract checks.*

### Q3: Has the contract been deployed to Orchard, and do you have a transaction hash?
* **Answer:** **No.**
* **Evidence:** In `packages/core/src/deployments.json`, `"0x00a89d7494cb3d16858a74e5cae1a965d14df5a2"` is an offline vanity address generated by `generate-quai-wallet.ts` to satisfy Cyprus-1's `0x00` shard byte prefix. `deployTxHash` is completely missing. Deployment script `deploy-orchard.ts` is implemented but has not been broadcasted with funded faucet tokens.

### Q4: Has any real or funded key ever been committed or pasted anywhere, and is the repo public?
* **Answer:**
  - **Repo is PUBLIC** at `https://github.com/Asheshykyk/NeuroNova.git`.
  - **Committed Keys:** Hardhat Account #0 (`0xac0974…REDACTED`), mock key (`0x012345…REDACTED`), and Render vault signer key (`0xcb29ee…REDACTED`) are committed in git history.
  - **Funded Status:** None have ever held real funds, but all must be treated as permanently compromised test keys.

### Q5: Is the Render service live and publicly reachable, and is `main` protected?
* **Answer:**
  - **Branch Protection:** `main` is **NOT protected** (direct pushes succeed).
  - **Render Status:** Blueprint `render.yaml` is in Git, but no active live URL is bound. If deployed, the unauthenticated read endpoints (`/api/v1/events`, `/api/v1/batches`) and committed signer key represent an immediate information disclosure vulnerability.
